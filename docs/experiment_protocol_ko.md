# 온라인 실험과 오프라인 확장 프로토콜

2026-09-28 · 구현 전 계획. 학습 수치와 예산은 제안이며 측정된 처리량·최적 설정·실험 결과가 아니다. 환경 명세는 [버그와 과제 설계](bug_specifications_ko.md)를 따른다.

## 1. 먼저 고정할 것

초기 주 실험은 H1/H2, fixed/mutant, 준비된 재고에서 시작하는 기호 관측 과제다. 한 실행에서 결함 여부는 고정한다. 모든 방법이 같은 과제 보상과 행동 공간을 사용한다.

학습은 정책·가치 함수·탐험 모델·옵티마이저를 처음부터 초기화한다. 정상 정책의 선행 학습, 이미지 입력, 여러 버그의 동시 활성화, goal conditioning은 초기 표에 섞지 않는다.

환경 파라미터와 초기 배치는 알고리즘 결과를 보고 최종 평가에 맞추지 않는다. 지도와 시작 상태의 조합을 학습/검증/평가 집합으로 나누고 실제 상태 해시로 중복을 검사한다. 초기 규모 후보는 1,024/128/256개이며, 생성기의 다양성과 중복률을 먼저 확인한다. 같은 배치의 회전·작은 변형이 평가로 새지 않도록 생성 템플릿 단위도 기록한다.

## 2. PPO와 RND의 공통 설정

| 설정 | 초기값 | 선택 이유 또는 확인 사항 |
| --- | --- | --- |
| 관측/행동 | Classic symbolic 1,345차원 / 17개 | 이미지 인코딩 성능을 분리 |
| 병렬 환경 | 512 | 모든 방법에서 고정. 실제 메모리·처리량 확인 후 동결 |
| rollout 길이 | 64 | update당 32,768 transitions |
| PPO epochs / minibatches | 4 / 8 | minibatch 4,096. 샘플 재사용과 optimizer step 수 기록 |
| 정책·외재 가치 네트워크 | 각각 hidden 3층, 폭 256, tanh | 공식 FF 구조. 실제 모델 경로를 검증 |
| optimizer | Adam, epsilon 1e-5 | 공식 PPO 기준 |
| 초기 학습률 | 2e-4, 고정 | 파일럿을 연장해도 앞 구간 스케줄을 바꾸지 않기 위해 annealing 해제 |
| gamma / GAE lambda | 0.99 / 0.8 | 기준 구현의 시작값. 긴 credit assignment의 제약을 별도 확인 |
| clip / entropy / value coef | 0.2 / 0.01 / 0.5 | 초기에는 스윕하지 않음 |
| global gradient clip | 1.0 | RND의 추가 value gradient와 상호작용할 수 있음을 기록 |
| reset | 환경별 독립 reset | optimistic reset으로 초기 상태가 중복 배정되는 효과를 피함 |
| 평가 간격 | 1,048,576 환경 transitions | PPO 32 updates마다 |
| 평가 시 학습 | 없음 | optimizer·RND predictor·정규화 통계를 갱신하지 않음 |

환경 step은 **모든 worker를 합한 transition 수**다. 512개 환경의 동시 step 1번을 1 transition으로 세지 않는다. 같은 seed 번호가 서로 다른 알고리즘에서 같은 초기 가중치나 이후 궤적을 만든다고 가정하지 않는다.

유한 시간 목표이므로 과제의 512-step 제한은 가치 계산에서도 종료로 취급한다. 파일 저장이나 rollout 경계 때문에 중간에 잘린 것은 과제 종료가 아니다. 실제 terminal observation과 reset 후 observation을 구분하고, 원본 no-auto-reset 환경과 wrapper를 조합해 reset을 정확히 한 번 수행한다.

### RND 설정과 필요한 대조군

검토한 `ppo_rnd.py`는 내재 보상의 크기와 정책 advantage의 가중치를 따로 갖는다.

$$
A^{\mathrm{actor}}=A^{\mathrm{ext}}+\beta A^{\mathrm{int}}.
$$

- `RND_REWARD_COEFF=1.0`, `RND_GAE_COEFF=beta=0.01`에서 시작한다.
- RND target/predictor는 각각 hidden 3층, 폭 256, 출력 512로 고정한다. predictor LR은 3e-4, target은 고정이다.
- 본 과제는 유한 에피소드이므로 `RND_IS_EPISODIC=True`로 설정한다. 기준 구현 기본값과 다름을 명시한다.
- 정책 너비를 바꿔도 RND 폭·출력·학습률은 함께 바꾸지 않는다.
- 외재/내재 보상, 두 advantage의 표준편차와 `beta * std(A_int) / std(A_ext)`를 기록한다. 분모가 거의 0인 구간은 별도로 표시한다.

RND 구현은 내재 value network도 추가한다. 따라서 PPO 대 PPO+RND의 차이가 순수한 보상 하나의 효과라고 주장하지 않는다. 차이가 나타나면 **같은 RND 코드에서 beta=0**인 대조군을 한 과제에 추가해 탐험 신호의 효과를 확인한다. 이 대조군에서도 보조 모델을 유지한다. 공유 global gradient clipping 때문에 보조 value loss가 actor update 크기에 영향을 줄 수 있으므로 단순히 ‘추가 head는 무관하다’고 가정하지 않는다.

## 3. 단계별 실행 예산

먼저 H0의 짧은 스크립트 검사와 H1의 정상/예외 경로를 검증한다. 그다음 H1 파일럿을 시작하고, 평가가 작동하면 H2를 추가한다.

한 파일럿은 PPO 256 updates에 해당하는 **8,388,608 transitions**, 본 실험의 시작 후보는 1,024 updates에 해당하는 **33,554,432 transitions**다. 이 예산이 충분한지는 아직 알 수 없다. 파일럿 후 더 긴 예산이 필요하면 본 실험 전 공통 horizon을 다시 정한다. 성공한 방법만 더 오래 학습하지 않는다.

| 단계 | 조합 | 학습 실행 수 | 총 환경 transitions |
| --- | --- | --- | --- |
| P: 파일럿 | 2과제 × 2버전 × PPO/RND × 3시드 | 24 | 약 0.201B |
| A: 기본 비교 | 2과제 × 2버전 × PPO/RND × 8시드 | 64 | 약 2.147B |
| W: 크기 추가 | H1 × 2버전 × PPO 폭 128/512 × 8시드 | 32 | 약 1.074B |
| Q: PQN 추가 | 2과제 × 2버전 × PQN-FF × 8시드 | 32 | 약 1.074B |

W의 폭 256은 A의 동일 실행을 재사용한다. H1을 크기 비교의 우선 과제로 미리 지정한다. H1이 쉬워서 제외되면 H2로 조용히 바꾸지 않고 수정 이유와 새 탐색 단계임을 기록한다. P/A/W/Q를 모두 실행하면 약 **4.50B transitions**이며, 튜닝·추가 진단·평가 비용은 별도다. 작은 표도 전체 예산은 작지 않으므로, 각 단계는 앞선 결과가 질문을 남길 때만 진행한다.

3시드는 오류·난도 확인용이고 8시드는 초기 연구 예산이다. 8개에서 발견 확률은 12.5% 단위로만 관측되므로 좁은 차이를 확정할 수 없다. 더 정밀한 추정이 필요하면 효과와 분산, 비용을 보고 시드 수를 다시 정한다. 파일럿 시드와 본 실험 시드는 분리한다.

### 하이퍼파라미터 선택

첫 P 단계는 기본값 한 개로 시작한다. 문제가 확인되거나 본 비교를 확정할 때만 작은 검증을 추가한다.

1. PPO의 LR 후보는 `{1e-4, 2e-4, 4e-4}`. 폭 256에서 정상 과제 검증 성능으로 고르고 두 과제의 평균 결과를 공개한다.
2. RND는 같은 PPO LR을 우선 사용하고 beta `{0.003, 0.01, 0.03}`만 검증한다. 두 과제×두 버전의 검증용 배치에서 외재 목표 성공률의 동일 가중 평균으로 고르며 최종 평가의 위반률로 고르지 않는다. 동률이면 작은 beta를 선택한다.
3. 크기 스윕의 주 결과는 공통 LR이다. 순위가 나타나면 작은/큰 모델에 동일 LR 후보를 허용한 민감도 결과를 추가한다. 개별 seed에 유리한 값을 선택하지 않는다.
4. 각 탐색은 후보당 2개 별도 시드와 파일럿 예산을 상한으로 두고, 사용한 튜닝 transitions를 공개한다. 튜닝이 본 실험보다 커지면 후보를 추가하지 않는다.

gamma 0.99에서 긴 지연 보상이 약해지는 문제가 확인되면 `{0.99, 0.995}` 비교를 별도 진단으로 한다. gamma·LR·entropy·beta·너비를 한꺼번에 스윕하지 않는다. 설정을 바꾸면 그 설정의 기준 방법도 다시 비교한다.

### 환경 난도는 한 축씩 바꾼다

초기 배치 생성기의 목표값은 기회 상태까지의 이동 d≈4, 위반 사건 이후 목표까지의 유효 스크립트 길이 L≈12다. 이는 최적 경로 길이라는 주장이 아니며 실제 유효 경로와 시작 상태를 기록한다. 16×16에서 동시 만족이 어려우면 지도만 억지로 늘리지 않고 fixture 단계에서 값과 생성 규칙을 개정한다.

| 별도 진단 | 후보 | 유지할 것 | 해석 |
| --- | --- | --- | --- |
| 기회 도달 비용 | d∈{0,4,12} | 후속 경로, 자원, 모델 폭 256 | 발견 전 도달·탐험 부담 |
| 결과까지의 지연 | L∈{4,12,24} | 기회 상태에서 시작, 자원, 모델 폭 256 | 위반 이후 가치 전파·제어 부담 |

위 숫자는 과제 생성용 목표값이다. 실제 경로 길이가 달라지면 분포를 공개한다. 첫 진단은 H1의 d만 바꾸고 PPO/RND, 조건당 3시드와 파일럿 예산을 사용한다. d=4 기준 결과를 재사용할 수 있으면 추가 d 두 개에 총 12 runs가 필요하다. L과 d, 모델 크기를 동시에 교차시키지 않는다. 지연을 늘리는 과정에서 단서가 관측에서 사라지면 기억 부담도 달라진다는 한계를 명시한다.

## 4. 신경망 크기와 알고리즘 비교의 의미

원본 FF 구조는 actor와 critic이 각각 독립적인 hidden 3층 MLP다. D=1,345, A=17, 폭 w일 때 actor+critic의 파라미터 수는 다음과 같다.

$$
N(w)=4w^2+2714w+18.
$$

| hidden 폭 | actor | critic | 합계 |
| --- | ---: | ---: | ---: |
| 128 | 207,505 | 205,441 | 412,946 |
| 256 | 480,529 | 476,417 | 956,946 |
| 512 | 1,223,185 | 1,214,977 | 2,438,162 |

이것은 소스 구조로 계산한 값이며 실제 초기화 결과로 확인한다. RND의 내재 critic·predictor·고정 target은 이 표에 포함하지 않는다. 학습 가능한 파라미터, 고정 파라미터와 추론에 필요한 파라미터를 각각 보고한다.

처음에는 actor와 critic을 함께 키우므로 결과는 **PPO 시스템 크기**의 효과다. 정책 표현력만의 효과라고 쓰지 않는다. 차이가 남으면 `(actor 폭, critic 폭)=(128,256),(512,256),(256,128),(256,512)`를 제한적으로 비교한다. 동일한 데이터로 배우는 효과인지 보려면 후속 offline 실험이 필요하다.

### PQN-FF

`purejaxql/pqn_craftax.py`를 바탕으로 시작한다. 비교용 프로파일은 hidden 3층·폭 256, layer norm, input normalization, RAdam, LR 1e-4, gamma 0.99, Q-lambda off로 제안한다. 이는 저장소의 4층·폭 1,024 기본 프로파일과 다르며 논문 점수 재현 설정이라고 부르지 않는다.

PQN의 탐험은 epsilon 0.1→0.005, 전체 예산의 첫 20% 동안 선형 감소를 출발점으로 한다. optimizer LR은 PPO처럼 고정한다. 환경 수는 512, update당 rollout 1, epoch/minibatch는 1/1이다. 순환 PQN의 다른 기본값을 섞지 않는다.

같은 환경 transitions라도 PQN과 PPO의 optimizer step 수·배치·샘플 재사용·정규화가 다르다. 환경 효율과 실측 시간 효율을 둘 다 보고하되, 이것을 완전한 연산량 일치 실험이라고 부르지 않는다. PQN 결과가 나쁘면 검증 LR `{5e-5,1e-4,2e-4}`를 동일한 2시드 파일럿 예산으로 확인한 뒤 해석한다.

### RNN과 관측 진단

H2에서 정보 이력이 병목으로 남을 때 PPO-RNN/PQN-RNN을 추가한다. 먼저 FF와 RNN에 같은 이전 행동 입력을 주거나 둘 다 제외해 입력 차이를 통제한다. GRU hidden 256, truncated BPTT 길이 64를 출발점으로 하고 에피소드 시작에서만 상태를 초기화한다. rollout 경계에서는 hidden을 유지하고 gradient만 끊는다.

원본 RNN과 FF는 깊이·공유 구조·활성 함수도 다르므로 official 구현끼리의 비교만으로 기억의 인과 효과를 주장하지 않는다. 필요하면 같은 인코더/heads에서 GRU 유무만 바꾼 진단 모델을 만든다. 전체 지도 관측도 자동으로 Markov가 되는 것은 아니며, 생존 타이머·식물 나이·남은 시간 등 숨겨진 상태를 함께 점검한다.

## 5. 평가와 통계

최종 체크포인트를 주 결과로 한다. 학습 중 최고 점수를 본 시험 지도에서 고르지 않는다. 검증 평가와 최종 평가 지도는 분리한다.

- 중간 평가는 검증 배치 64개, 최종 평가는 보류한 배치 256개를 초기 예산으로 한다.
- 주 활용 평가는 모든 방법에서 greedy/argmax 행동을 사용한다. PPO의 학습된 확률적 정책 평가도 별도 보고해 결정론적 변환으로 성능을 잃는 경우를 숨기지 않는다. 두 결과를 섞어 유리한 쪽만 택하지 않는다.
- mutant에서 학습한 같은 체크포인트를 mutant와 fixed 모두에서 평가한다. fixed에서 학습한 정상 정책도 양쪽에 평가해 버그를 만나기 쉬운 정책인지 확인한다.
- 동일한 초기 상태 집합을 공유하되 첫 행동 분기 뒤에도 궤적·난수가 같다고 가정하지 않는다.

필수 지표는 다음과 같다.

| 양 | 정의와 해석 |
| --- | --- |
| 첫 위반 시간 T | 전체 환경 transitions 기준. 같은 벡터 step의 사건들에 worker index로 가짜 시간 순서를 부여하지 않음 |
| 발견 곡선 F(B) | 예산 B 이내 위반을 경험한 학습 시드 비율 |
| 제한 평균 발견 시간 | `min(T,B)`의 평균과 검열 표시. 미발견을 빼고 평균 내지 않음 |
| 재현률 | 동결 정책 평가 에피소드 중 위반이 발생한 비율 |
| 과제 성능 | 목표 성공률과 capped completion time |
| 기회 노출 | 위반을 발동할 수 있는 전제 상태 방문. 단순 방문 횟수와 방문한 에피소드 수를 구분 |
| 기여 진단 | 사건의 직접 자원/도구 변화와 패치 환경에서의 성능 변화 |

기회 상태 근처에서 새로 학습하는 실험은 별도 과제다. 일반 시작의 발견 실패 실행을 제외하는 대신, 모든 방법에 같은 기회 상태 분포를 준다. 이 진단에는 도달 비용이 제거되므로 일반 시작 결과와 평균 내지 않는다.

패치 환경에서 성능이 떨어져도 그 자체가 최적성이나 인과 이해의 증거는 아니다. 사건 직전의 유효 상태에서 동일 행동을 fixed/mutant로 분기해 직접 효과를 확인한다. mutant에서만 가능한 음수 재고 상태를 fixed의 자연스러운 상태라고 가정해 복사하지 않는다.

독립 단위는 학습 실행이다. 시드별 목표 성능을 먼저 계산하고 실행 간 평균·불확실성을 보고한다. 평가 지도도 변동 원인이므로 필요하면 시드와 지도를 함께 재표집한다. 발견 여부는 작은 표본의 비율 구간을 사용한다. 수백 평가 에피소드를 수백 학습 시드처럼 계산하지 않는다.

수치 오류·실행 중단·판정기 오류와 정상적인 학습 실패를 분리한다. 후자는 제외하지 않는다. 코드 오류로 재실행하면 영향 범위와 모든 관련 조건의 처리 방식을 기록한다.

## 6. 정상 학습 이후 적응

기본 비교가 끝난 뒤, H1의 fixed PPO 체크포인트에서 시작하는 실험을 우선한다.

1. 정상 환경에서 공통 사전 학습 예산을 사용한다. 좋은 체크포인트만 골라 적응시키지 않는다.
2. 각 체크포인트를 복제해 fixed 계속 학습과 mutant 적응으로 분기한다.
3. 양쪽 모두 새 rollout에서 시작하고 이전 rollout은 폐기한다. 주 실험에서는 정책·가치·Adam 상태를 복사하고, optimizer reset은 별도 ablation으로 둔다.
4. mutant scratch를 동일 추가 예산 및 동일 전체 예산의 두 관점에서 비교한다. 사전 학습 비용을 공짜로 처리하지 않는다.

RND를 추가할 때는 target·predictor·내재 critic의 유지 여부까지 명시해야 한다. 첫 적응 실험은 PPO만 사용해 이 변수를 줄인다.

적응 파일럿의 구체적 후보는 H1, 폭 256, 정상 학습 8,388,608 transitions 후 같은 체크포인트를 fixed/mutant로 분기해 각각 8,388,608을 추가하는 것이다. 공통 정상 체크포인트 3개라면 사전 학습+두 분기의 비용은 약 75.5M transitions다. 정상 과제가 그 예산에서 학습되지 않으면 적응 결과를 규칙 고착으로 해석하지 않는다. scratch 대조군과 장기 본 실험의 추가 비용은 별도로 산정한다.

이 실험은 online pretraining 후 dynamics shift다. 원래부터 있던 드문 사건의 발견, 고정 데이터셋에서의 offline 학습, offline-to-online fine-tuning과 구분한다.

## 7. 오프라인 확장을 위해 지금 저장할 데이터

모든 단계에서 run manifest, 학습 설정, 코드 SHA, 실제 모델 크기, hardware, 누적 환경/gradient step, compile 및 학습·평가·기록 시간을 보존한다.

전이는 `episode_id, t, obs, action, reward_ext, next_obs, terminated, time_limit, collection_cut, bootstrap_discount`를 기본으로 한다. 실제 terminal observation을 보존한다. 버그 이벤트, full-state snapshot과 수집 정책 정보는 분석용 메타데이터로 구분한다. 학습에는 명시적으로 허용한 관측과 외재 보상만 제공한다.

원시 float32 관측과 다음 관측을 100만 전이 보존하면 `2 × 1345 × 4 × 10^6 = 10.76 GB`다. 모든 온라인 스텝을 이 방식으로 저장하지 않는다.

- 타일은 categorical ID, 몹은 bit/boolean 채널, 재고·생존 변수는 원래 수치로 저장해 관측을 손실 없이 복원한다. 실제 복원 동등성을 검사한다.
- 결과와 독립적인 episode 표본을 사전에 정한 수집률로 저장한다. 여러 학습 단계와 여러 수집 정책 seed를 포함한다.
- 위반 주변 궤적은 별도 보관하되, 이 자료는 사건을 기준으로 선택된 enrichment archive라고 명시한다.
- snapshot은 필요한 checkpoint/사건에 저장하고, 재생에 필요한 reset·RNG 정보와 action sequence를 보존한다. 버전이 달라져도 자동 재생된다고 가정하지 않는다.

## 8. 첫 offline 실험: 증거의 양

H1부터 시작한다. 모든 데이터는 **같은 mutant 전이 커널에서 실제로 실행**해 수집한다. fixed 학습 정책을 수집자로 쓸 수는 있지만, fixed의 다른 전이를 mutant 데이터에 조건 정보 없이 섞지 않는다.

공통 정상 행동 pool과 버그 활용 pool을 만들고 총 전이 수 N=1,000,000을 출발점으로 한다. 독립적인 활용 에피소드 수를 `k ∈ {0,1,10,100}`으로 바꾸며 같은 양의 일반 데이터를 대체한다. 총량을 맞추는 과정에서 terminal 구조나 next observation을 손상시키지 않는다. 실제 사건 수·시작 상태 분포·성공률·목표 보상량도 함께 보고한다.

이 조작은 희귀 행동뿐 아니라 성공 보상과 방문 상태도 바꾼다. 따라서 초기 결과는 ‘이런 활용 경험의 추가 효과’다. 버그라는 의미만의 효과를 보려면 비슷한 가치의 드문 정상 전략 궤적을 추가한 대조군을 후속으로 사용한다.

| 데이터 조건 | 의미 | 제한 |
| --- | --- | --- |
| D₀: 사건 0개 | 정상 행동만으로 얻은 공통 데이터 | 수집 전부터 비정상 상태로 시작한 궤적도 배제. 증거 없는 버그 발견을 요구하지 않음 |
| Dₖ: 사건 및 활용 궤적 k개 | 드문 예외를 선택하고 학습하는 능력 | 단순 모방으로도 풀릴 수 있으므로 BC 필수 |
| D_partial: 위반 후 목표 미달 | 우연한 사건이 가치 있는 행동으로 연결되는지 | 성공 이후 상태·행동의 지원이 없으면 조합이 아니라 일반화 문제 |
| D_comp: 독립 궤적의 연결 가능한 조각 | 후속 단계의 경험 조합 | 실제 상태 호환성·지원 여부를 별도로 검증한 경우에만 사용 |

H1에서 철 -1인 제작 후 상태는 정상 제작 후 철 0인 상태와 다르다. 이를 같은 상태인 것처럼 연결하면 안 된다. full-state 분석에서 필요한 전이가 있는지 확인하고, local 관측의 aliasing도 보고한다. 성공 궤적을 파일 단위로 나누기만 하는 조건은 one-step TD의 새로운 과제가 아니다.

### 알고리즘과 offline 예산

첫 비교는 BC, categorical actor를 쓰는 discrete IQL, discrete CQL(Q-learning)이다. 논문 근거는 [연구계획서](research_plan_ko.md#9-출처와-검토-버전)의 [6–7]에 둔다. continuous-control TD3+BC를 행동을 임의로 연속화해 바로 가져오지 않는다.

- 공통 기호 관측, hidden 폭 256과 고정 데이터. 각 방법의 actor/Q/V 개수 및 총 파라미터는 따로 보고한다.
- 초기 학습 예산 후보는 batch 256, 100,000 gradient steps, LR 3e-4다. 데이터 passes와 validation 학습 곡선을 함께 확인한다.
- IQL은 expectile 0.7, `exp(3 × advantage)` 형태의 가중치와 상한 100을 출발점으로 한다. 가중치 정의를 명시해 inverse temperature와 temperature를 혼동하지 않는다.
- CQL은 discrete action의 log-sum-exp penalty를 사용하고 alpha 1에서 시작한다. `{0.1,1,10}`의 보수성 스윕은 두 데이터 수준에서 먼저 확인한다. alpha는 최적값으로 주장하지 않는다.
- k와 네트워크 너비를 동시에 전부 스윕하지 않는다. 먼저 같은 구조로 증거의 양에 대한 반응을 본다.

초기 검증은 `3방법 × k={0,10} × 데이터 구성 1개 × 초기화 2개 = 12 runs`다. 통과하면 데이터 구성 seed 3개와 learner seed 3개를 사용한 `3 × 4 × 3 × 3 = 108 runs`가 확장 예산 후보다. 데이터 구성 seed와 신경망 seed는 다른 변동 원인이며 9개의 완전히 독립적인 데이터셋으로 취급하지 않는다.

Offline 학습 중 환경 전이를 replay buffer에 추가하지 않는다. 검증 환경 평가를 하이퍼파라미터 선택에 썼다면 ‘온라인 검증 허용’ 프로토콜이라고 공개하고 평가 상호작용을 별도 계산한다. 순수 데이터만으로 모델을 고르는 설정과 섞지 않는다.

## 9. Offline-to-online 및 GCRL의 후속 위치

Offline으로 학습한 IQL 체크포인트에서 고정된 추가 온라인 예산으로 적응한다. 출발 데이터는 우선 D₀와 D₁₀ 두 조건이다. actor/critic/target/optimizer의 유지 여부, 온라인/오프라인 minibatch 비율과 buffer 관리를 고정한다. 초기 후보는 50:50이며, 업데이트에 필요한 첫 온라인 데이터가 생기기 전에는 혼합 update를 수행하지 않는다.

scratch online IQL과 동일 초기 정책의 BC warm start 등을 통해 offline 데이터의 기여를 비교한다. online PPO와의 순위만으로 사전 학습 효과를 판단하지 않는다. 사전 학습과 추가 온라인 비용을 함께 보고한다. CQL fine-tuning은 보수성 해제 스케줄이라는 새 변수가 생기므로 첫 확장에서는 보류한다.

GCRL은 같은 예외 기술을 여러 목표에 재사용하는 질문이 남을 때 도입한다. 현 단계에서 고정 목표를 쓰는 것만으로 goal-conditioned benchmark라고 부르지 않는다. 전이 확인 없이 미래 목표를 재라벨링하는 데이터 증강도 추가하지 않는다.

## 10. 구현 완료로 인정할 산출물

첫 학습 전에 필요한 것은 환경 factory, H0/H1 최소 회귀 검사, 정상/예외 스크립트, 독립 판정기, 단일 reset 경로, reward/terminal 로그다. H2는 음수·양수 경계의 읽기/쓰기와 JIT/vmap 결과까지 확인한다.

본 스윕 전에는 환경·배치 분포·보상·horizon·평가 규칙·코드 SHA를 manifest로 고정하고, 실제 throughput과 데이터 저장 크기를 측정한다. 이후 자동 실행용 설정 파일을 만든다. 현재 저장소에는 이 **계획 문서만 있으며**, 환경 패치나 학습 명령이 구현되었다고 간주하지 않는다.
