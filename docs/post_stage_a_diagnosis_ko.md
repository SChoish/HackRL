# Stage A 이후: 평가 확인과 정상 경로 구간 진단

2026-09-29. Stage A 28셀 요약과 코드 트리를 기준으로 한 실행 계획이다.
학습량·폭·알고리즘을 더 늘리는 비교는 이 진단 이후로 미룬다.

## 결정

다음 학습은 R-M patched fixed의 정상 경로에서 남은 행동 수를 줄인 최대 9개 진단 셀이다.
그 전에 저장 정책 재평가와 기존 update 로그 집계로 mutant의 최종 평가 하락이
실제 정책 변화인지 확인한다. 평가 경로에 문제가 있으면 새 학습보다 그것부터 고친다.

## 1. 기존 산출물에서 먼저 확인

mutant seed 0–2의 1.049M, 4.194M, 16.777M checkpoint를 모두 사용한다.
성공 checkpoint만 선택하지 않는다. 해당 실행의 config와 코드 트리를 복원한
별도 평가기로 mode 32회, sample 256회를 수행한다. checkpoint 간 평가
reset/action seed 집합을 공유하되, 정책 분기 이후 동일 궤적을 가정하지 않는다.

- summary와 최종 checkpoint가 같은 가중치인지, variant/dynamics/관측/목표/종료 설정이 일치하는지 확인한다.
- 저장 직전 평가와 저장 후 재로딩 평가를 같은 키로 비교할 수 있는 경우 그대로 대조한다.
  기존 키가 보존되지 않았다면 과거 stochastic 평가의 완전 재현을 주장하지 않는다.
- train 성공률은 전체 누적뿐 아니라 마지막 128 updates, 마지막 32 updates에서
  성공 수 / 완료 에피소드 수로 다시 계산한다. update별 비율의 단순 평균을 사용하지 않는다.
- 같은 frozen policy를 학습용 rollout 경로에서도 실행해 첫 에피소드 성공률을 계산하고
  평가기와 대조한다. auto-reset 뒤 여러 완료 에피소드를 세는 비율과 worker별 첫 에피소드 비율을 구분한다.
- reset, 제작 직후, 다이아몬드 앞의 실제 상태에서 행동 확률과 value를 기록한다.

누적 성공률만 높고 최근 train/sample 평가가 함께 낮다면 후기 정책 퇴화와 부합한다.
sample은 높고 mode만 낮다면 행동 선택 규칙에 따른 차이다.
같은 frozen policy와 같은 조건인데 rollout 경로별 결과가 다르면 새 학습 전에
평가·reset·집계 구현을 고친다. 이 확인만으로 LR이나 entropy가 원인이라고 결론 내리지 않는다.

## 2. 정상 경로의 후반에서 새 PPO 학습

정상 행동열은 `UP, DO, DOWN, MAKE_IRON_PICKAXE, DOWN, DO`다.
아래 시작 상태는 patched fixed 원본 reset에서 해당 prefix를 실제 실행하여 생성한다.
재고만 수동으로 지급하지 않는다.

| 실행 | 시작 상태 | prefix | 잔여 | seed | 예산/셀 |
|---|---|---|---|---|---|
| D1 | 철 곡괭이를 들고 다이아몬드 앞 | 5 | 1 (`DO`) | 0–2 | 1,048,576 |
| D2 | 작업장에서 철 곡괭이 제작 직후 | 4 | 2 (`DOWN`, `DO`) | 0–2 | 1,048,576 |
| D3 | 철 채굴 후 작업장으로 돌아온 상태 | 3 | 3 (`MAKE`, `DOWN`, `DO`) | 0–2 | 1,048,576 |

총 상한은 9 × 1,048,576 = 9,437,184 transitions다.
새 가중치·optimizer로 시작한다. PPO 폭 256, 128 env × 64 step, 128 updates,
4 epochs × 8 minibatches, LR 2e-4 고정을 유지한다.
같은 seed의 초기 파라미터를 조건 간 공유한다.

보상은 원래 diamond 달성 +1만 사용하며 action masking, 추가 shaping,
재료 보충, curriculum을 섞지 않는다. prefix가 만든 시간·허기·재고·방향·map을 보존하고
원래 H=512 종료를 적용한다. prefix는 학습 transition에 포함하지 않는다.

평가·저장은 update 0, 32, 64, 128에 수행한다.
같은 진단 시작점의 mode 32회/sample 128회와 원래 reset의 평가를 별도로 보고한다.
원래 reset 평가는 분포 이동 검사이며, 후반 학습만 한 정책의 성공을 요구하는 통과 기준이 아니다.

D1부터 실행한다. D1이 전혀 학습되지 않으면 D2/D3로 확대하지 않는다.

## 3. 판단과 중단

- D1조차 학습 성공이 전혀 없다면 보상 전달·done·관측·gradient·정상 suffix 검증을 우선한다.
- D1은 학습하지만 D2가 실패하면 이동과 채굴 연결 구간을 진단한다.
- D2는 학습하지만 D3가 실패하면 제작 선택과 그 후 행동 연결 구간을 진단한다.
- D3까지 학습하지만 default가 실패하면 초기 채굴·복귀·재료 보존을 다음 개입 대상으로 삼는다.

이 비교는 시작 분포, 보상까지의 거리와 실패 기회를 함께 바꾼다.
특정 인과 원인 하나를 입증하는 실험이 아니라 병목 구간을 좁히는 진단이다.
D3 성공을 전체 과제 해결로 보고하지 않는다.

구현은 `StartMode.R_M_D1` / `R_M_D2` / `R_M_D3`이다.
시작 상태는 원래 reset 뒤 정상 prefix를 실제 step으로 실행해 만든다.

## 4. mutant 재평가 결과 (2026-09-29)

산출물: `runs/overnight_stage_a/a2x_mutant_recheck.json`.
1.05M·4.19M·16.78M를 재로딩해 mode 32 / sample 256 / 학습 rollout 첫 에피소드 32를 같은 평가 시드로 대조했다.

| seed | 최근 32/128 train | 1.05M·4.19M reload | 16.78M mode32 | 16.78M sample256 | 학습경로 첫 에피소드 |
|---|---|---|---|---|---|
| 0 | 0 / 0 | mode=sample=1.0 | 0 (길이 338, 사망) | 0 | mode=sample=0 |
| 1 | ≈1.0 / ≈0.999 | mode=sample=1.0 | 0 (길이 338) | 0.0039 | mode=sample=0 |
| 2 | 0 / 0 | mode=sample=1.0 | 0 (길이 338, 사망) | 0 | mode=sample=0 |

저장 직전 `eval.json`과 재로딩 평가는 같은 방향으로 맞았다.
같은 frozen policy를 학습 rollout 경로에 넣어도 평가기와 일치했다.
평가·reset·집계 구현을 고치지 않는다.

seed 0/2는 후반 train 자체도 이미 0이다. 1.05M·4.19M 정책은 재현 가능하고, 16.78M에서 정책이 무너진다.
seed 1은 마지막 8 update의 train 성공이 거의 1.0인데 저장 가중치는 실패한다.
롤아웃은 업데이트 전 가중치로 수집되고, 저장은 그 직후 업데이트 뒤 가중치다.
누적 train 성공률 ≈0.99는 후기 붕괴를 가린다. sample만 살아 있는 형태가 아니다.

고정 정책의 reset 행동: 16.78M에서 seed 0/1/2 모두 mode가 `DOWN`이다.
3-step exploit의 `MAKE`가 아니다. 다이아몬드 앞(prefix 5)에서는 seed 0이 `DO`를 유지하고
seed 1은 `MAKE`로 돌아간다. 후기 붕괴는 시작 행동에서 먼저 보인다.

평가 경로가 정상이므로 D1(patched fixed, prefix 5, 3 seed × 1.05M)만 먼저 넣었다.
D1 통과는 “다이아몬드 앞에서 마지막 채굴을 학습한다”는 뜻이다.
제작 후 이동·채굴 연결이 병목이라고 확정하지 않는다. 그 위치는 D2·D3로 좁힌다.

D1 학습 전 sample 성공률은 이미 0.45–0.49였다. 처음부터 보상 경험이 충분하다.
이번 결과는 그 시작 분포에서 PPO가 성공 행동을 강화한다는 근거다.
희소한 성공을 발견하거나 여러 행동을 연결하는 능력까지 검증한 것은 아니다.
원래 reset 실패는 예상 가능한 분포 차이다.

D2는 같은 설정으로 새 초기화로 학습한다. 성공률과 함께 첫 보상 시점,
다이아몬드 앞 도달률, 도달 후 채굴 성공률을 본다.
D2가 성공하면 D3로 진행한다. D1 정책을 D2 시작에서 평가하는 것은
D2 실패 시의 보조 진단이며, D2 학습 자체를 대체하지 않는다.

mutant 16.78M 재평가는 평가 경로 불일치를 해소하지 못했다.
경로 간 결과는 일치했고, 저장 가중치의 후기 붕괴가 남는다.
실패 궤적(위치·방향·재고·종료)은 `a2x_mutant_fail_trajectories.json`에 따로 둔다.
