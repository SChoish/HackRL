# 버그와 과제 명세

2026-09-28 · 연구계획 v2의 구현 전 명세. 아래 코드는 변경 의도를 나타내는 의사코드이며 실행 검증된 패치가 아니다. H0/H1/H2는 결함 ID이고 L/R/B-E/M/H는 과제 ID다. 난이도별 초기 상태·목표·시간 제한은 [과제 목록](benchmark_catalog_ko.md)을 기준으로 한다.

## 1. 공통 구현 계약

원본 코드의 검토 커밋은 [연구계획서의 출처](research_plan_ko.md#9-출처와-검토-버전)에 고정한다. 각 환경은 동일한 생성기와 reset seed에 대해 같은 초기 상태를 만드는 `fixed`와 `mutant`로 구성한다. 버그는 에피소드나 개체별 숨겨진 난수로 선택하지 않고 실행 설정으로 고정한다.

평가 판정기는 환경 전이와 별도로 구현한다. 변형한 함수가 반환한 ‘성공’ 플래그만 믿지 말고 직전 상태·행동·직후 상태의 좌표, 자원 및 객체 변화를 검사한다. 판정 결과는 로그에만 기록한다. 정보 딕셔너리 전체를 신경망 입력으로 넘기지 않는다.

기존 17개 행동을 유지한다. 정상 계약을 기준으로 행동을 미리 마스킹하면 버그 행동을 시도할 수 없으므로 그런 마스크는 사용하지 않는다. 버그가 만든 음수 재고를 관측 전처리에서 0으로 잘라 사실상 패치하지 않는다.

고정 fixture는 모든 상태 필드를 일관되게 만든다. 식물 타일과 성장 배열, 몹과 `mob_map`, 재고와 초기 업적, timestep과 생존 변수 등을 맞춘다. 미리 지급한 도구는 시작 시점의 과제 진행으로 간주하고 거짓 신규 업적 보상을 만들지 않는다.

### 과제 설정

R-M(H1)·B-M(H2)은 다음 프로파일을 공통으로 사용한다. 다른 7개 과제의 목표·재고·시간 제한은 과제 목록을 따른다.

- 16×16 지도 후보. 원본 생성기를 축소해도 된다고 가정하지 않고, 별도의 작은 reset fixture를 만든다.
- 기존 기호 관측 1,345차원과 17개 행동. 목표는 버전별로 고정된 ‘다이아몬드 1개 획득’이므로 목표 벡터는 추가하지 않는다.
- 최장 512 행동. 종료는 목표 달성, 사망 또는 시간 제한이다.
- 보상은 다이아몬드 최초 획득 시 +1, 나머지는 0. 원본 업적·체력 보상은 로그에만 남긴다. 버그 발동·제작·철 획득 보상은 별도로 주지 않는다.
- 시작 체력·음식·물·에너지는 9, 생존 규칙은 유지한다. 초기 주 비교에서는 적 생성과 기존 몹을 끈다. 물·휴식·정상 경로의 실행 가능성을 검사한다.
- 정상 채굴과 버그 경로가 모두 가능해야 한다. 벽은 원본 규칙으로 채굴 가능한지까지 고려한다. 보이는 경로만 검사하고 새로운 제작·채굴 경로를 무시하지 않는다.

이 수치와 보상은 파일럿 후보이며 정상 학습과 경로 검증을 통과한 뒤 동결한다. reward shaping이 필요하면 fixed/mutant에 같은 정상 업적 shaping을 적용한 별도 과제로 등록한다. 위반 보상을 뒤늦게 추가해 같은 과제의 결과로 합치지 않는다.

각 과제의 주 지표는 **목표 성공률**이다. 부 지표로 제한 시간 내 미성공 실행의 완료 시간을 해당 과제의 H로 둔 capped completion time을 사용한다. R-M/B-M에서는 H=512다. 성공한 실행만의 평균 시간은 부가적으로 구분해 보고한다. 서로 다른 목표·H를 가진 과제의 원시 시간을 직접 평균 내지 않는다.

## 2. H0: 수확 후 성장 나이 초기화 누락

### 근거와 변경

GBGallery TowerDefense Bug 8은 탑 파괴 후 연관된 스킬 객체가 해제되지 않는 현상을 보고한다. 여기서는 ‘본체 상태와 연관 상태의 갱신 불일치’라는 유형만 참고한다. 원본 버그가 반복 보상이나 잔류 공격을 제공했다는 주장은 하지 않는다.

Craftax-Classic의 `do_action`은 익은 식물을 수확하면서 타일을 미성숙 식물로 바꾸고, `update_plants_with_eat`으로 성장 나이를 0으로 만든다. 같은 게임 스텝 뒤쪽의 `update_plants`는 나이를 증가시키고 600 이상인 식물을 익게 만든다.

```python
# 정상: 식물 식별과 호출 조건은 그대로 둔다.
ages = ages.at[harvested_plant_index].set(0)

# 변형: 수확한 식물의 나이를 초기화하지 않는다.
ages = ages
```

수확 보상, 음식 상한, 상호작용 거리와 타일 갱신은 그대로 둔다. 특정 좌표나 plant index에서만 발생하게 하지 않는다. 같은 수확 처리 경로를 사용하는 모든 식물에 적용한다.

### 최소 검증과 판정

1. 정상적인 성장 배열에 등록된 익은 식물과 그 앞의 플레이어를 배치한다.
2. 음식이 9 미만인 상태에서 `DO`를 수행한다.
3. fixed에서는 나이가 초기화되고, mutant에서는 수확 후 갱신을 거쳐 다시 익는지 확인한다.
4. 다음 스텝에 다시 `DO`를 하여 두 버전의 차이를 검사한다.

독립 판정기는 식물별 마지막 수확 시각을 별도로 추적한다. 정확한 성장 타이밍은 정상 구현의 회귀 검사로 고정한다. 음식이 최대치여도 불법 재수확은 사건으로 기록하되, 실제 식량 이득과 구분한다.

식물의 나이는 원본 기호 관측에 직접 드러나지 않는다. 반복 수확은 같은 위치·방향의 반복 행동으로 쉽게 재현될 수 있으므로 H0의 성공을 복잡한 유연성으로 해석하지 않는다.

### 연구상 위치

H0는 판정기·로그·버전 비교 검사부터 시작한다. L-E는 음식 회복의 쉬운 대조군으로 포함하고, L-M/L-H는 생존과 다이아몬드 목표를 함께 쓰는 후보로 둔다. 식량뿐 아니라 물·휴식·정상 식량 경로를 검증한다. 식물 옆에 머무는 반복만으로 충분하면 장기 계획 과제로 해석하지 않는다. L-M/L-H의 활용 이득이 없으면 해당 슬롯을 미확정으로 남긴다. 쉬운 L-E의 대규모 너비 스윕은 우선하지 않는다.

## 3. H1: 재료 하한 오류에 의한 철 곡괭이 제작

### 근거와 변경

GBGallery TowerDefense Bug 5는 최소 레벨 1 규칙을 어기고 레벨 0이 되는 현상이다. 하한 조건 위반이라는 유형을 참고하며, 원본 게임에 철 재고나 음수 자원이 있었다고 주장하지 않는다.

`do_crafting`의 **철 곡괭이 레시피 한 곳**에서 철 조건만 바꾼다.

```python
# 나무·돌·석탄과 제작대·화로 조건은 동일하다.
has_iron = inventory.iron >= 1  # fixed
has_iron = inventory.iron >= 0  # mutant

# 성공 시 원래의 자원 차감과 산출물 증가는 그대로 실행한다.
iron_after = iron_before - int(crafted_iron_pickaxe)
```

철 0에서 제작하면 철 -1과 철 곡괭이 1개가 남을 것으로 예상한다. 이후 -1은 `>= 0`을 만족하지 않으므로 **무한 제작 버그가 아니다**. 다른 철 레시피는 수정하지 않는다. 원본 `cap_inventory`는 상한만 제한하므로 하한 동작을 추가로 검증한다.

### R-M의 과제 프로파일

- 목재·석재·석탄을 각각 1개, 목재 곡괭이·석재 곡괭이를 각각 1개 지급한다. 철·철 곡괭이·다이아몬드는 0이다.
- 제작대와 화로를 원본 인접 조건으로 이용 가능한 곳에 배치한다. 원본 제작 인접성은 대각선을 포함하므로 판정기도 이를 반영한다.
- 정상 채굴 가능한 철 광석과 다이아몬드, 접근 경로를 제공한다.
- 정상 경로: 철 채굴 → 작업장 복귀 → 철 곡괭이 제작 → 다이아몬드 채굴.
- 예외 경로: 철 없이 제작 시도 → 다이아몬드 채굴.

첫 검사는 제작 가능 위치에서 시작한다. 주 과제에서는 작업장까지의 이동을 추가하고 위치·방향을 바꾼다. ‘작업장까지의 거리’와 ‘철 채굴 우회 거리’를 동시에 스윕하지 않는다. 먼저 하나의 배치 분포를 고정한다.

초기화에서 상위 곡괭이만 지급하면 충분하다고 가정하지 않는다. 검토한 원본 채굴 조건은 자원 종류별 해당 곡괭이 필드를 직접 확인하므로 정상 경로에 필요한 하위 곡괭이도 명시한다.

### 판정과 의미

- 위반 사건: 직전 철이 0이고 원래 다른 전제 조건이 충족된 상태에서 철 곡괭이가 증가하며 철이 -1이 됨.
- 재현: 새로운 배치에서도 같은 관계가 반복됨.
- 후속 활용: 해당 도구를 얻고 실제 다이아몬드를 채굴하는 상태 전이를 추적함.
- 반사실 검사: 동일한 사건 직전 상태에서 그 제작 행동을 fixed에도 실행하면 제작되지 않음.

음수 재고는 정책이 경험할 수 있는 실제 증거다. 관측 공간의 선언된 범위만 동일하게 넓히고 값 자체를 버그 조건에서만 숨기거나 자르지 않는다. 정책 관측에 판정기 플래그를 추가하지 않는다.

H1이 측정하는 것은 도구 사용의 발명이 아니라, 기존의 제작 전제 조건에 대한 예외를 시도하고 후속 과제에 연결하는 능력이다. 바로 옆 작업장에서 제작 버튼을 누르는 것만으로 모든 방법이 해결하면 쉬운 과제로 남기고 주 크기 스윕을 실행하지 않는다.

## 4. H2: 지도 경계 밖 상호작용

### 근거와 변경

GBGallery TowerDefense Bug 7은 스킬 영향 범위의 계산 오류다. 공간 검증이라는 유형만 참고하며 원래 원인이 음수 인덱싱이었다고 주장하지 않는다.

`do_action`은 바로 앞 좌표 `player_position + DIRECTIONS[player_direction]`를 참조한 후, 지도 내부 여부와 몹 공격 여부에 따라 지도·재고 등의 갱신을 적용한다. 이 중 **지도 내부 여부에 의한 거부만 제거**한다.

```python
apply_tile_effects = in_bounds(state, target) and not did_attack_mob  # fixed
apply_tile_effects = not did_attack_mob                             # mutant
```

`DO` 여부, 자원별 도구 요구, 몹 공격 우선순위는 유지한다. 이동 함수와 제작대 인접성은 변경하지 않는다. 이는 상호작용 전체의 범위 검사 누락이므로 광석 외에 물·식물·잔디 등에 미칠 수 있는 효과도 조사하고 기록한다.

음수 인덱스가 마지막 행/열을 참조하면, 위쪽 또는 왼쪽 경계 밖으로 상호작용하여 반대쪽 자원을 얻을 가능성이 있다. 음수 read/write, JIT/vmap 동작은 실제 실행으로 확인해야 한다. 양의 범위 초과가 대칭적으로 감긴다고 가정하지 않는다.

### B-M의 과제 프로파일

- H1과 같은 종류의 시작 재고를 지급하되 **제작 코드는 정상**이다.
- 접근 가능한 위쪽 경계, 대응하는 아래쪽 행의 철 광석, 정상적인 철 채굴 경로, 작업장과 다이아몬드를 배치한다.
- 정상 경로: 반대쪽까지 이동하여 철 채굴 → 작업장 → 철 곡괭이 → 다이아몬드.
- 예외 경로: 위쪽 경계에서 바깥을 바라보고 `DO` → 철 획득 → 작업장 → 철 곡괭이 → 다이아몬드.
- 첫 검증에서는 경계에 서서 시작한다. 주 과제에서는 경계까지 이동해야 하며, 이후 별도 진단으로 도구나 자원을 먼저 준비하게 한다.

기존 이동 처리에서는 막힌 방향으로 이동을 시도해도 바라보는 방향이 바뀐다. 따라서 새 회전 행동을 추가할 필요는 없다. 원본 이동의 다른 경계 동작과 혼동되지 않도록 첫 fixture의 주변에 용암을 두지 않는다.

채취한 광석은 반대쪽 지도에서 실제로 제거되어야 한다. 제거되지 않고 재고만 늘면 다른 부작용이며 별도 사건으로 기록한다. 양의 범위 초과에서 읽기와 쓰기가 다르게 처리되는 경우도 검사한다. 하나의 root cause에서 생긴 여러 효과를 몰래 ‘광석 순간이동 한 종류’로 축소해 보고하지 않는다.

### 관측과 일반화

원본의 local 관측에서는 반대편 광석이 보이지 않는다. 따라서 다음 두 난도를 구분한다.

1. **규칙 이용:** 관련 경계 구간에 채취 가능한 자원이 항상 존재하고, 위치만 여러 배치로 바뀐다. 경계를 따라 시험하고 재고 변화로 확인할 수 있다.
2. **정보 기억:** 먼저 반대편 자원을 관측한 뒤 되돌아와야 하거나, 자원이 없는 지도도 섞인다. 이 경우 FF와 RNN의 비교가 필요하다.

B-E/B-M은 1번을 출발점으로 하고 B-H는 2번의 위치 정보 활용 후보로 둔다. 2번에서 FF/RNN 차이가 나도 곧바로 네트워크 크기 효과라고 보고하지 않는다. 경계를 훑는 정책으로 충분하면 기억이 필수라고 주장하지 않는다. 고정 fixture 하나의 경계 위치를 외우는 것을 줄이기 위해 경계상의 좌표·초기 거리·작업장 위치를 바꾸고 평가 배치를 분리한다. 위쪽에서 학습해 왼쪽에서 평가하는 것은 방향 전이 실험이지 동일 분포 평균에 포함할 항목이 아니다.

### 독립 판정

의도된 좌표가 지도 밖인지 정수 좌표로 먼저 검사한다. 그 행동으로 자원·타일이 바뀌었는지 확인하고, 실제 변경된 좌표와의 거리를 기록한다. 정책이 경계에 갔다는 이유만으로 위반 처리하지 않는다. 후속 철 곡괭이와 다이아몬드 획득까지 연결해 활용을 평가한다.

## 5. 대조군과 진입 기준

모든 task의 fixed/mutant 쌍에서 다음 네 검사를 통과해야 한다.

| 검사 | 확인할 사항 |
| --- | --- |
| 정상 경로 | 동일 초기 상태에서 fixed/mutant 모두 목표 달성 가능 |
| 예외 경로 | 사건 직전까지 같은 스크립트가 동작하며 결정적 행동에서만 차이가 생김 |
| 비관련 행동 | 결함 조건과 무관한 상태·행동에서 전이 차이가 없음. 같은 상태와 난수 키로 단일 스텝 비교 |
| 이득 | 버그를 활용한 유효 경로의 목표 완료 시간 또는 성공 가능성이 개선됨. 단순한 사건 빈도 증가는 불충분 |

스크립트 정상 경로의 시간은 최적 정상 경로의 하한이 아니다. ‘정상 최적보다 빠르다’고 주장하려면 작은 과제에서 탐색으로 검증하거나 충분히 강한 정상 정책을 비교해야 한다. 초기에는 정상 경로 존재와 이득의 후보만 확인한다.

판정기가 정상 실행에서 위반을 보고하거나, 고정 초기 상태의 불일치가 발견되면 학습을 시작하지 않는다. 실제로 한 가지 변형이 여러 차이를 만들면 명세를 개정하고 버전 번호를 바꾼다.

## 6. 의도적으로 보류한 방향

- **특정 식물/좌표에만 예외:** 구현 메커니즘과 관측 가능한 단서 없이 rarity를 만드는 방식은 사용하지 않는다.
- **제작대 캐시가 영구 유지됨:** 현재 코드에 없는 캐시 상태와 무효화 규칙을 새로 만드는 부담이 있어 첫 버전에서는 제외한다.
- **새로운 취소·환불·분해 기능:** Craftax에 없는 게임 메커니즘을 만들어야 하므로 Workshop Escape식 복제 버그는 보류한다.
- **무조건 벽 통과·무적:** 우연히 발동해도 바로 이득을 얻는 환경은 학습 능력 구분이 약할 수 있어 우선하지 않는다.
- **보상 숫자만 증가시키는 오류:** 외재 목표를 실제로 달성하는 현재 연구와 분리한다.
